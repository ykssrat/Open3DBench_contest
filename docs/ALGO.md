## 1. 问题建模：为什么不能用贪心

基线做法是"逐个 HBT 向外螺旋搜索最近的空闲格点"。这是**次序相关的贪心**：先占位者抢占公共最优格点，后到者被迫劣化，且没有任何回溯机制。

把问题写清楚：设 HBT 集合 `H`（bp_fe 为 1149 个），合法键合格点集合 `S`，每点容量 1。若单个 HBT `h` 放在格点 `s` 的代价 `c(h,s)` 只依赖 `(h,s)`（可分离），则该问题是**带互斥约束的设施选址**，其全局最优解等价于

```
min  Σ_h c(h, σ(h))
s.t. σ: H → S 为单射
```

即**最小代价二分匹配 / 最小费用流**，存在多项式时间的**全局最优解**。贪心最近空位对它可以任意劣（反例见 `hbt_mcmf.py` 自测：贪心 101，最优 4）。本算法因此彻底弃用螺旋占位，改用全局指派。

## 2. 代价函数

### 2.1 线长项（HPWL 增量）

对 HBT `h`，取其 BOT / TOP 两个子网上的真实 cell 引脚坐标（排除 HBT 自身），记为 `B_h`、`T_h`（由 `export_hbt_topology.csv` 给出，含每引脚 slack）：

```
Δ(h,s) = [HPWL(B_h ∪ {s}) − HPWL(B_h)] + [HPWL(T_h ∪ {s}) − HPWL(T_h)]
HPWL(P) = (max_x − min_x) + (max_y − min_y)
```

用"增量"而非"绝对线长"是关键：绝对 HPWL 会把所有 HBT 都推向同一片区域，增量才刻画"这个 HBT 放这里要额外付多少线长"。该项用 numpy 向量化，对全部 (HBT × 格点) 组合一次算完（秒级）。

### 2.2 时序权重（归一化）

`W = 1 + β · clamp(−slack / |WNS_ref|, 0, 1)`，`β = 4`（`HBT_TIMING_BETA`）。

- 分母是本设计自身的参考 WNS（从导出数据的有限 slack 中自标定，**不硬编码**），因此与 slack 的绝对量级无关；
- 分子硬 clamp 到 `[0,1]`，权重上限 `1+β`，任何隐藏用例都不会失控；
- 这替换掉了早期 `1 + |slack|·10` 的写法——后者在 slack 量级为 ns 且分布很宽时会让少数超关键网支配整个目标，把其余上千个 HBT 的线长诉求压没。

### 2.3 最小扰动项

`+ ε · |s − 原坐标|₁`（`ε = 0.05`）。代价平台区内优先"不搬动"，避免无意义的等价换位，也让输出更稳定、可复现。

### 2.4 可行性保证

- 每个 HBT 的**原位置一定被补进候选格点集**，所以"不搬"永远是可选项 ⇒ 模型最优代价 **≤** 现状代价；
- 解出后若模型代价反而高于现状（数值/建模误差），直接采用原位置；
- 格点合法性在候选生成阶段一次性剪掉：必须落在 `ORIGIN + n·12800` 键合网格上、footprint 完全在 die 内、不与任何非 HBT 元件 footprint 重叠；互斥由流容量 1 保证。

## 3. HBT 之间的相互干扰：拥塞价格 + 不动点迭代

多个 HBT 挤在同一片区域会互相抬高拥塞，这一项**不可分离**（依赖"谁和谁一起选了哪"），单纯的最小费用流无法表达。用拉格朗日松弛把它解耦成价格：

1. `ρ⁰ = 0`，解全局指派；
2. 用本轮被占格点构造密度场：以格点为冲激，做半径 `r`（默认 3 个格点）的盒式滤波，得到每个候选格点的局部占用密度 `d(s)`（纯 numpy/scipy，**不需要跑 GRT**，秒级）；
3. 价格强度自标定：`λ = α · std(基础代价) / std(密度)`（`α = 0.35`），即让价格项的离散度约为基础代价离散度的固定比例——同样**不硬编码绝对值**，对不同规模/不同 die 的隐藏用例自动成立；
4. 令 `ρ = λ · d/max(d)`，重解指派；
5. 迭代 2~3 轮，在"模型代价"与"p95 密度"之间取折中最优解（代价几乎相同但拥塞明显更低时优先低拥塞）。

这是标准的**价格型不动点迭代**：每轮子问题都是可精确求解的全局指派，价格承担子问题之间的耦合信息。

## 4. 求解器

`hbt_mcmf.py` 提供三级后端，按可用性自动降级，保证离线环境也能跑：

1. **ortools** `SimpleMinCostFlow`（C++，最快；整数费用，内部按 `SCALE=1000` 缩放）；
2. **scipy** `linear_sum_assignment`（Jonker-Volgenant，稠密矩阵）；
3. **纯 Python 最小费用流**：连续最短路 + Johnson 势函数，无第三方依赖；scipy 缺失时按每行 Top-K（`HBT_TOPK`，默认 48）候选稀疏化后求解。

规模：1149 HBT × 数千~数万格点。前两个后端为亚秒~数秒级，远小于 GRT 自身耗时（bp_fe 基线 35s）。求解器预算目标：< 30s。

## 5. Runtime（权重 25%）

- 求解器本身是多项式算法 + 向量化实现，相对 GRT 可忽略；
- `global_route_die_by_die.tcl` 中两个 die 的 GRT pass（bottom metal2-10 / upper metal11-20）**输入相同、互不依赖、原本串行**，可并发为两个子进程（各 ≤16 线程，总计 ≤32 线程，符合赛题限制），合并步骤不变，零质量风险地砍掉约一半 GRT 时间。（此项为待实施的优化点。）

## 6. 红线合规

| 红线 | 保障 |
|---|---|
| 禁止修改非 HBT 元件布局 | 求解器只输出 HBT 坐标；`grt_prepare.tcl` 的导出段是纯读取 |
| HBT pitch 6.4um（Cut Spacing DRC） | 候选格点严格取 `ORIGIN + n·12800` 网格（DBU=2000 ⇒ 6.4um） |
| 任何 guide 不得跨 die | 子网与 die 的归属关系不变，本阶段不新增/拆分线网 |
| HBT 总数 ≤ 容量 | 阶段 A **不新增** HBT，只重排已有 1149 个 |
| 禁止对 bp_fe 硬编码 | 全部参数由导出数据自标定（WNS 参考、格点 pitch/origin、价格强度 λ） |

## 8. 后续：阶段 B（Metal Layer Sharing）

定位：**MLS 是拥塞疏导工具，不是万能增益**。每个 HBT 带 3Ω + 0.6fF 延迟代价，HBT 预算必须花在**非关键长网**上，用下 die M2-M3 资源的释放去换关键网的 TNS/WNS。

- 候选：对非关键、高 HPWL 的网生成 2/3 段切分候选（几何二分 + HBT 落点）；
- 收益 `= ΔHPWL − λρ·Δ拥塞 − μ·临界度·延迟代价`；
- 选择：在 ≤580（bp_fe 免费额度）HBT 预算与格点容量约束下做**预算约束的联合选择**（knapsack / 最小费用流 + 价格迭代），而非"按收益排序一路加到预算用完"的贪心；
- 网表手术（Tcl）：建 `LS_HBT_<id>` 实例、拆出 `<net>__MLS__S<id>__BOT|__TOP`、重连 ITerm；随后**全体 HBT（旧+新）再联合重解一次指派**。
